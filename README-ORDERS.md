# Заказы и кабинет Юрмани

Клиент выбирает товары в каталоге → открывает корзину → «Оформить заказ» → оставляет имя, телефон, город и способ получения → получает номер сохранённого заказа. Регистрация и MAX клиенту не нужны. Оплаты на сайте нет. Менеджер подтверждает фасовку, наличие, доставку и итоговую сумму.

Кабинет `/manager/`: вход по личному логину и паролю; список заказов, поиск, статусы, ответственный, следующий звонок, комментарии и история. Заказы сохраняются в SQLite на сервере. Уведомления по почте — дополнительный канал: сбой почты не удаляет заказ.

## Посмотреть на Windows

Нужен Python 3.10 или новее. Распакуйте архив, откройте папку `urmani-main`, запустите **START-ORDERS-WINDOWS.cmd**. При первом запуске создайте логин латиницей, имя менеджера и пароль минимум 12 символов. При вводе пароля символы не отображаются — это нормально. Запомните пароль, общего пароля в архиве нет.

Откроется `http://127.0.0.1:8000/`, кабинет — `http://127.0.0.1:8000/manager/`. Оставьте окно программы открытым. Используйте тестовые данные: это локальная проверка, не рабочий сервер для клиентов. Старый запуск через `python -m http.server` не поддерживает сохранение заказов.

Для телефона нужно запустить сервер с `--host 0.0.0.0` и заранее задать `URMANI_ORIGIN=http://IP-КОМПЬЮТЕРА:8000`; телефон и компьютер должны быть в одной сети. Форма принимает запросы только с настроенного адреса.

## Размещение для реальных клиентов

GitHub Pages обслуживает статические файлы и не запускает этот Python-сервис. Не заменяйте рабочий сайт новым архивом на Pages до подготовки сервера: оформление заказов требует API. Для этой версии нужен постоянно работающий сервер с диском, HTTPS и резервным копированием. Размещать базу следует на выбранном российском сервере; данные не отправляются в стороннюю CRM. Обмен с 1С в эту версию не входит.

На сервере с Docker Compose:

1. Загрузите содержимое `urmani-main`. Создайте `.env` по `.env.example`, укажите домен и полное зарегистрированное имя ИП — оператора данных. Утвердите опубликованный текст обработки данных до приёма реальных заказов.
2. `docker compose build`
3. `docker compose run --rm web python -m server.manage create-user` — создайте личный аккаунт. Пароль вводится интерактивно, не передаётся в командной строке.
4. Направьте DNS домена на сервер, откройте входящие порты 80/443. Сохраните существующие записи почты и Google-подтверждение. Запустите `docker compose up -d web proxy`. Caddy получает HTTPS-сертификат. Порт приложения 8080 наружу не опубликован.
5. Проверьте заказ на сайте, вход в `/manager/`, состав и сумму. Политика доступна по `/privacy.html`. Новый сервис обслуживает и прежние страницы каталога/SEO по тем же адресам.
6. Для уведомлений заполните SMTP в `.env`, используйте отдельный пароль приложения почты, затем `docker compose --profile mail up -d mail`. Реальные пароли не передавайте в переписке и не загружайте в GitHub. Без SMTP заказы видны в кабинете, уведомления не отправляются.

Перед переводом DNS сохраните старую версию и план отката. Перед первым рабочим заказом проверьте весь путь с телефона и письмом на настроенный адрес. Тестовые заказы отделяйте статусом «Отменён» либо используйте отдельный тестовый сервер. Базу с рабочими заказами не удаляйте.

## Учётные записи и резервная копия

Добавить менеджера: `docker compose exec web python -m server.manage create-user`.
Сбросить пароль: `docker compose exec web python -m server.manage reset-password LOGIN` — прежние сессии завершатся.
Отключить менеджера: `docker compose exec web python -m server.manage disable-user LOGIN`. Последнего активного менеджера отключить нельзя.

Сделать согласованную копию: `docker compose exec web python -m server.manage backup /var/lib/urmani/backup-YYYY-MM-DD.sqlite3`, затем скопировать её из контейнера и хранить отдельно от сервера с ограниченным доступом. Настройте ежедневный запуск и хранение нескольких копий. Не копируйте только живой файл SQLite без WAL. Для восстановления остановите web/mail, сохраните текущую базу и замените `orders.sqlite3` проверенной копией; старые `-wal`/`-shm` должны быть убраны вместе со старой базой. Сначала проверьте восстановление на тестовом сервере.

Очередь почты повторяет отправку до 8 раз. После окончательной ошибки заказ остаётся в кабинете; настройку SMTP нужно исправить. Письмо в редком случае может прийти повторно после остановки процесса между отправкой и отметкой результата. Проверяйте новые заказы и в кабинете, а не только в почте.

## Проверки

`python -m unittest discover -s server/tests -v`

Проверяются сохранение и повтор отправки, параллельные запросы, проверка цен/состава/согласия, восстановление квитанции, вход и ограничение попыток, права/CSRF, конфликт изменений менеджеров, статусы/история, недоступность служебных файлов и сохранность заказа при сбое почты.

Все 1096 товаров и SEO-страницы сохранены. Checkout и кабинет исключены из индексации. Источник рекламы сохраняется в заказе по UTM, если клиент пришёл с такими метками. Сквозная телефония и оплата не подключены.
